# Сайт гостевого дома ZАРЯ

Сайт: **заря-ольхон.рф** (в технической записи `xn----7sbuskebm2c1d3a.xn--p1ai`).
Админка: **заря-ольхон.рф/admin/**

Всё содержимое сайта (тексты, фото, цены, контакты, меню, SEO) лежит в `content.json` и меняется через админку. Админка сохраняет правки прямо в этот репозиторий на GitHub, а хостинг подхватывает их сам.

```
index.html        страница сайта — собирается автоматически, руками не править
content.json      всё содержимое сайта
img/              фотографии
assets/           стили, скрипт, шрифты
admin/            админка
src/              исходники стилей и скрипта (для разработчика)
build.mjs         пересборка из исходников (для разработчика)
favicon.png, apple-touch-icon.png, og-image.jpg, robots.txt, .nojekyll
.github/          автовыкладка на обычный хостинг по FTP (вариант Б)
```

## Шаг 1. Залить новую версию в репозиторий

В репозитории сейчас лежит старый `index.html` на 2,9 МБ. Его нужно заменить всеми файлами из этой папки.

**Через сайт GitHub, без программ:**

1. Откройте репозиторий → **Add file → Upload files**.
2. Выделите в папке сайта всё, **кроме** `_backup` и `.claude`, и перетащите в окно браузера. Папки (`img`, `admin`, `assets` и т. д.) перетаскиваются целиком.
3. Внизу нажмите **Commit changes**.

**Или через GitHub Desktop:** скопируйте файлы в папку репозитория, затем **Commit to main → Push origin**. Файл `.gitignore` сам не пустит в репозиторий `_backup` и `.claude`.

> Проверка: в корне репозитория должны быть `index.html`, `content.json`, `.nojekyll` и папки `admin`, `assets`, `img`.

## Шаг 2. Включить хостинг

Выберите один вариант.

### Вариант А. GitHub Pages — бесплатно, рекомендую

1. Репозиторий → **Settings → Pages**.
2. **Source:** *Deploy from a branch*. **Branch:** `main`, папка `/ (root)` → **Save**.
3. Через 1–2 минуты сайт откроется по адресу `https://ИМЯ-АККАУНТА.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/`.

Бесплатно GitHub Pages работает только для **публичного** репозитория. Секретов в нём нет: токен админки в репозиторий не попадает.

**Подключить домен заря-ольхон.рф:**

1. **Settings → Pages → Custom domain**: впишите `xn----7sbuskebm2c1d3a.xn--p1ai` → **Save**. GitHub добавит в репозиторий файл `CNAME` — не удаляйте его.
2. В панели регистратора домена (где покупали .рф) откройте настройки DNS и сделайте:
   - для `@` четыре **A-записи**: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - для `www` **CNAME-запись** на `ИМЯ-АККАУНТА.github.io`;
   - старые A- и CNAME-записи для `@` и `www` удалите.
3. Подождите, пока обновится DNS (обычно час-два, иногда до суток). Затем в **Settings → Pages** поставьте галочку **Enforce HTTPS**.

### Вариант Б. Обычный хостинг (Beget, Timeweb, REG.RU и т. п.)

GitHub остаётся хранилищем, а после каждой публикации из админки сайт сам выкладывается на хостинг по FTP.

1. В панели хостинга найдите FTP-доступ: **сервер**, **логин**, **пароль** и **папку сайта** (часто `public_html/` или `заря-ольхон.рф/public_html/`).
2. Репозиторий → **Settings → Secrets and variables → Actions**:
   - вкладка **Secrets** → *New repository secret*: `FTP_USERNAME` (логин) и `FTP_PASSWORD` (пароль);
   - вкладка **Variables** → *New repository variable*:
     - `FTP_SERVER` — адрес сервера, например `ftp.example.ru`;
     - `FTP_DIR` — папка сайта **со слешем на конце**, например `public_html/`;
     - `FTP_PROTOCOL` — `ftps`, если хостинг его поддерживает (необязательно).
3. Вкладка **Actions** → «Выкладка на хостинг по FTP» → **Run workflow**. Зелёная галочка — сайт выложен. Дальше всё работает само после каждой публикации.

## Шаг 3. Подключить админку

**1. Выпустите токен доступа** (это пропуск админки в репозиторий):

1. Откройте [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new).
2. **Token name:** «Админка сайта». **Expiration:** максимальный срок.
3. **Repository access:** *Only select repositories* → выберите репозиторий сайта.
4. **Permissions → Repository permissions → Contents:** *Read and write*.
5. **Generate token** → скопируйте токен. GitHub покажет его только один раз.

**2. Войдите в админку:** откройте `ваш-сайт/admin/` и заполните поля:

- **Репозиторий** — `имя-аккаунта/название-репозитория`;
- **Ветка** — `main`;
- **Токен** — тот, что скопировали.

Токен хранится только в этом браузере. На чужом компьютере после работы нажмите «Подключение и файлы → Выйти». Когда срок токена кончится, выпустите новый так же.

**3.** В разделе «Подключение и файлы» впишите репозиторий. Тогда при следующем входе его не придётся вводить заново.

## Как пользоваться админкой

- **Слева** — все части сайта: контакты, шапка и меню, первый экран, разделы страницы по порядку, подвал, SEO, цвета.
- **Справа** — живой предпросмотр. Нажмите на любой блок в нём, и откроется его редактор. Переключатель вверху показывает сайт на телефоне, планшете и компьютере.
- **Тексты:** `*слово*` — курсив (в заголовках он выделяется фирменным цветом), `**слово**` — жирный, `[текст](https://ссылка)` — ссылка. Пустая строка начинает новый абзац. `{телефон}`, `{max}`, `{telegram}` и `{почта}` подставятся из контактов.
- **Фото:** кнопка «Загрузить» или перетаскивание на миниатюру. В галерею можно добавить сразу несколько фото. Админка сама уменьшит и сожмёт их: снимок с телефона на 5 МБ превращается примерно в 150–300 КБ. Подписывайте фото — это нужно поисковикам.
- **Разделы и блоки** можно добавлять, удалять, копировать, скрывать и менять местами стрелками ↑↓. Новый раздел появится в меню, только если добавить пункт в «Шапка и меню».
- **↶ / ↷** — отменить или вернуть действие. Неопубликованные правки сохраняются в браузере сами, даже если закрыть вкладку.
- **«Опубликовать»** сохраняет правки на GitHub, и через 1–2 минуты сайт обновляется. Фото, которые больше нигде не используются, удаляются из папки `img/`, но в истории остаются.
- **«История изменений»** — все прошлые публикации. «Открыть» загружает старую версию, «Опубликовать» возвращает её на сайт вместе с фото.

## Если что-то пошло не так

| Сообщение или проблема | Что делать |
|---|---|
| «GitHub не принял токен» | Срок токена истёк или он скопирован с ошибкой. Выпустите новый (шаг 3). |
| «У токена не хватает прав» | В настройках токена: *Contents → Read and write* и доступ к нужному репозиторию. |
| «Не нашёл репозиторий…» | Проверьте запись `имя-аккаунта/название` и ветку (бывает `master` вместо `main`). |
| Сайт не обновился | Подождите пару минут и обновите страницу с Ctrl+F5. На GitHub Pages статус виден во вкладке **Actions**. |
| Что-то сломали | «История изменений» → нужная версия → «Открыть» → «Опубликовать». |

## Для разработчика

- `node build.mjs` пересобирает `assets/style.css`, `assets/app.js` и `index.html` из `src/` и `content.json`. Нужна только после правок в `src/`. Тексты и фото меняются через админку.
- `admin/render.js` — общая сборка страницы: её используют и `build.mjs`, и админка (для предпросмотра и публикации). Поэтому результат совпадает байт в байт.
- Админка — статичные файлы без сервера. Она работает с GitHub через REST API: Git Data API для коммитов, Contents API для чтения.
